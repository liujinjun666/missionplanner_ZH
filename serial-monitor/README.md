# 遥测通信监听（zh-serial）

MP 插件 `zh-serial.cs`：在「飞行数据」页注入「遥测通信监听」勾选框（排在「飞控网口」右侧），
点开一个独立窗口，把 **MP 与飞控之间正在跑的所有 MAVLink 收发报文**实时显示出来，
并且可以直接在窗口里**发命令、写参数**。

> 早期版本曾尝试「另外开一个 COM 口抓物理字节」和「按 SERIALn 协议归属报文」，
> 两条路都已取消 —— 原因见下方「为什么只监听 MP 连接」。

## 三个页签

| 页签 | 内容 |
|---|---|
| **报文** | 收发双向报文列表 + 选中行的字段详情 + 十六进制 dump |
| **发送** | 发 `MAV_CMD` 命令（COMMAND_LONG）、写参数（PARAM_SET） |
| **打印** | `STATUSTEXT` 文本流，按严重级别着色 |

## 报文页

列表列：时间 / 方向 / 消息名 / ID / sysid:compid / seq / 帧长 / 内容摘要。

- 选中任意一行 → 下方「详情」区显示该报文的**全部字段**（结构体反射展开）与**十六进制 dump**（含 ASCII 列）。
- 报文表格每 200ms 批量刷新一次，行数封顶 5000 行，长时间挂机内存稳定。

### 过滤条件

| 控件 | 作用 |
|---|---|
| 关键字 | 逗号分隔多个词，匹配消息名或内容摘要 |
| 消息类型 | 下拉单选（「全部消息类型」+ 已出现过的类型），只显示某一类 |
| 多选… | 弹出 `CheckedListBox`，勾选多个类型同时看；支持全选 / 全不选 |
| 方向 | 全部 / 仅接收 / 仅发送（「仅发送」看 MP 主动发了什么） |
| 只看文本/打印 | 只留 `STATUSTEXT` 等文本类报文 |

类型下拉是**动态补项**的：只有真正收到过某类报文，它才会出现在列表里，
所以刚打开时只有「全部消息类型」一项是正常的。

### 工具按钮

暂停 / 继续、清空、保存日志（TSV，可直接用 Excel 打开）、导出原始帧（`.bin`，可喂给其它 MAVLink 工具离线分析）、置顶。

右键菜单：复制选中行、复制全部、导出选中原始帧。

状态栏：`收 xx / 发 xx / 丢弃 xx` + 实时速率（按**字节**算，不是按报文条数）；左侧显示数据源状态。

## 发送页

### 发送 MAV_CMD 命令（COMMAND_LONG）

目标 `Sysid` / `Compid` 可改（默认 1 / 1）。**选命令之后，参数区会换成这条命令专属的控件**——
下拉选项、带单位的数字框、勾选框，不需要记 P1~P7 的编号和含义。

全部 22 条预设，按用途分组：

| 分组 | 命令 |
|---|---|
| 飞行 | 400 解锁/上锁、22 起飞、21 降落、20 返航、192 引导到指定点、189 开始自动降落、16 飞往航点 |
| 模式 | 176 设置飞行模式（多旋翼全模式下拉） |
| 任务 | 300 开始任务、193 暂停/继续、179 设置 Home、201 设置 ROI、197 取消 ROI |
| 调参 | 178 修改速度、183 设舵机 PWM、184 重复舵机输出 |
| 维护 | 241 预检校准、246 重启/关闭飞控、401 跑预检、410 读 Home |
| 遥测 | 511 设置消息频率、512 请求消息 |

每条命令的参数界面举例：

- **400 解锁/上锁**：动作下拉（解锁/上锁）+「强制跳过预检」勾选
- **22 起飞**：起飞高度(m) + 航向（默认「用当前机头」，不指定时发 NaN）
- **176 设置模式**：模式下拉（STABILIZE…AUTO_RTL 共 25 个）
- **178 修改速度**：地速/空速下拉 + 速度 m/s + 油门%
- **511 设置消息频率**：消息类型下拉（**全量 MAVLink 消息表**）+ 频率 Hz（内部换算成微秒）+「恢复默认频率」勾选
- **241 预检校准**：陀螺仪 / 磁罗盘 / 加速度计 三个勾选
- **246 重启飞控**：重启飞控 / 关闭飞控 / 重启板载计算机 三选一

列表里没有的命令，选最后一项「**自定义命令…**」：右上角 ID 手动填，参数区变成 7 个通用数字框。

发送走 `MainV2.comPort.doCommand(sysid, compid, cmd, p1..p7, requireack: false)`，
在后台线程执行，结果回写到「发送状态」label。发出去之后切到「报文」页，
能看到自己发的 `COMMAND_LONG` 和飞控回的 `COMMAND_ACK`（含 result 码），这是最可靠的确认方式。

> 内部实现：每个参数控件用 `Reg(pIndex, () => 值)` 登记到取值函数表，
> 点发送时 `ReadArgs()` 统一读出来填进 p1..p7。加新命令只需在 `BuildArgs()` 里加一个 `case`。

### 写入参数（PARAM_SET）

填参数名 + 值点「写入」，走 `MainV2.comPort.setParam(sysid, compid, name, value, force: false)`。
例：`FLTMODE1=0`、`SERVO1_FUNCTION=70`。写前请确认参数名，写错不会报错但也没效果。

> **安全提醒**：解锁、起飞、重启飞控、校准这些命令会真的动飞机。
> 台架上先拿 `REQUEST_MESSAGE` / `SET_MESSAGE_INTERVAL` 这类只读命令试手。

## 为什么要听 MP 连接，不自己开串口

飞控的串口（SERIAL1/2/3）是**飞控板内部总线**，不是电脑的 COM 口。数据要想到达电脑只有三条路：

1. **固件封装成 MAVLink 从 MAVLink 口上报**（EFI→`EFI_STATUS`、GPS→`GPS_RAW_INT`…）—— 这条路 MP 已经全收下了，本工具直接读 MP 的报文即可，零成本。
2. **自己打开那个 COM 口抓字节** —— 串口是独占资源，MP 连着时抢不过来；要先让 MP 断开，而断开后 MP 自己的功能就没了。曾经实现过「接管」模式，实机验证代价大于收益，已删除。
3. **`SERIAL_PASS1/PASS2` 透传** —— 需要改参数、`PASSTIMO` 到时间才自动恢复，否则要重启飞控，风险高，未实现。

所以本工具的选择是：**只听 MP 当前连接这一条链路**。
好处是零配置、能看到发送方向、不影响 MP 正常工作；代价是看不到 MP 解析失败的物理层垃圾字节。

## 坑与约定（改这个文件前必读）

- **编译失败静默不加载**：MP 对成功和失败打的是同样的 INFO 日志，真正的错误只在 `PluginLoader.ErrorInfo`。
  排查手法：放一个 `zh-diag.cs` 把 `ErrorInfo` 写到 `C:/ProgramData/Mission Planner/zh_plugin_errors.txt`。
- **收包线程不能碰控件**：过滤条件在 UI 线程拍快照（`fltTextOnly` / `fltDir` / `fltText` / `selTypes` 都是 `volatile` / 整体替换），
  收包线程只读快照；直接读 `CheckBox.Checked` 跨线程会炸。
- **`selTypes` 只整体替换、不原地增删**：收包线程持有引用读 `Contains`，原地改 `HashSet` 会并发崩。
- **UI 不能被灌爆**：报文先入 `pending` 缓冲（上限 3000），200ms 定时批量上屏，超限计入「丢弃」。
- **列表上限 5000 行**，超出从头部删。
- **主题前景色**：MP 深色主题会把新建控件文字刷白，面板/表格/标签显式设 `ForeColor = Black`。
- **Dock 顺序**：`TabControl(Dock=Fill)` 必须 `SetChildIndex(tabs, 0)`，否则被顶部过滤面板压住。
- **控件注入要等锚点**：先找 `CHK_net`（飞控网口），找到才按 `anchor.Right + 8` 落位；
  最多等 8 秒（`loopratehz = 1`），找不到才退化到「玄云ECU」右侧，最后兜底加进「飞行数据」菜单。
- **事件挂钩要防重**：`AttachMp()` 用 `attached` 字段记录当前挂的是哪个 `MAVLinkInterface`，
  换了连接对象要重新挂；`DetachMp()` 在窗口关闭和 `Exit()` 时都要调。
- **发送用后台线程**：`doCommand` / `setParam` 会阻塞等串口，直接放 UI 线程会卡界面；回写控件统一走 `UiPost()`。

## 当前版本

## 验收点

- MP 连接飞控后勾「遥测通信监听」，报文页出现 `HEARTBEAT` / `SYS_STATUS` / `ATTITUDE`，方向「收」「发」都有
- 「消息类型」下拉里随运行时间逐渐出现更多类型；「多选…」勾两个类型后列表只剩这两类
- 发送页切命令时，下方参数区**整块换成该命令的控件**（如 176 出现模式下拉、241 出现三个校准勾选）
- 选 `512 · 请求消息` → 消息类型选 `HEARTBEAT` → 发送 →「发送状态」显示成功，「报文」页出现 `COMMAND_LONG` 与 `COMMAND_ACK`
- 打印页出现飞控的 PreArm / 模式切换文本，颜色随级别变化
- 连续跑 10 分钟不卡、不闪退、内存稳定
